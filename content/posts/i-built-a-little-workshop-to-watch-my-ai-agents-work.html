The short version

I built a small animated page, styled as a Tony Stark workshop, that shows my agents handing work to each other. It reads logs the agents already write, never calls a model, can't change anything and only works while the tab is open.

In the last post, A Crew of AI Agents Runs My Homelab, I introduced the crew: five agents, each with a job, all behind one chat. This one picks up where it left off.

Once they were running I couldn't get over one thing. I had no idea what they were actually doing. I'd send a message, wait a few seconds and get an answer. Somewhere in between, one agent had passed work to another, maybe a model had been swapped because the first choice was out of credit, and a few things had been checked. All of it invisible. I was trusting a black box that happened to be well behaved.

So I built a window into it: a small animated page, set in a Tony Stark style workshop, where each agent is a character and you can watch the hand-offs happen.

It's not a serious monitoring tool. It's a toy that happens to answer a real question, and building it was some of the most fun I've had on this project.

What you actually see

Each agent has its own pod with a name tag and the model it's running right now. The model comes from the data, not from a label I typed in, so if an agent quietly falls back to a different one, the tag changes and a small chip says so.

When I send a request, the director picks it up and walks it to a holographic table in the middle of the room. The specialist who owns the job steps up, does the work and passes the result back. A glowing reactor in the corner pulses with overall activity. A list of events runs down the side, and clicking one replays what happened: who talked to whom, in what order, how long each step took.

Making milliseconds visible

A hand-off between two agents often takes a few milliseconds. On a real timeline that's a blink you'd never see. So the page cheats, on purpose. When a hand-off is very fast, it stretches the moment so you can watch it, and shows the real number next to it so it stays honest. Why it costs nothing to run

The picture is built from data the agents already leave behind: a log of what each model call cost, a list of conversations, and the history of scheduled jobs. The page reads those files, works out what happened and draws it. There is no model in the loop.

  • It never calls a language model, so there are no tokens to pay for.
  • It never sees the text of your messages, only that a call happened, when, how long it took and which model served it.
  • It's read-only. It can't change anything and it can't send anything.
  • It only works while somebody has the page open. Close the tab and it goes back to sleep.

If you're careful about what your agents are allowed to do, you'll appreciate that the thing watching them has even fewer permissions than they do.

Where the idea came from

I didn't start from a blank page. Two open source projects got me thinking:

  • The Delegation by arturitu (github.com/arturitu/the-delegation), a visual take on agents handing work to each other.
  • Claw3D by iamlukethedev (github.com/iamlukethedev/claw3d), which puts a fleet of agents in a 3D space.

Both are great, and the inspiration is theirs. If you want something richer than mine, start there. I wrote my own for plain reasons. I didn't want something needing its own model key, since the point was a view that costs nothing and can't run up a bill. I wanted a very small footprint: one tiny container with no dependencies instead of a larger stack to maintain. And since my agents already write down everything the page needs, there was nothing to wire in except reading those files.

How it got built

I vibe coded it with Claude Code, in conversation, over a couple of sittings. I described the feel I wanted ("cartoon characters moving around, like a game, with Tony Stark's workshop"), looked at it, said what was wrong, and kept going.

The part I'm most glad I did properly was the boring part. Before it went anywhere near my real agents I had it write tests proving the page can't write to anything, can't see message text and can't reach a model. That's easy to skip when you're having fun, and it's why I'm comfortable leaving it running. It sits behind the same login as everything else in my lab, so it isn't exposed to the internet.

Build your own

You don't need my version. The recipe works for almost any agent setup:

  1. Find the trail your agents already leave. Most harnesses keep a cost log, a session list or a job history. That's your event feed.
  2. Turn calls into events. A burst of calls from one agent, then another agent a moment later, is a hand-off. Timestamps and agent names are enough.
  3. Keep it read-only and free. Read files, never call a model, never show message text. Only poll while someone is watching.
  4. Make it yours. Mine is a workshop with armor pods and a holo table. Yours could be a train station, a kitchen, a spaceship, a tiny office with a coffee machine. A mood is far easier to enjoy than a table of numbers.

Tell your coding assistant what the scene should feel like, point it at the files, and iterate until it makes you smile.

Living with it

I expected a gimmick. What I got was a much better sense of how the crew behaves. I can see at a glance when one agent is carrying most of the work, when a fallback model has taken over, and when a request I thought was simple turned out to need three hand-offs.

And it's nice to look at. Watching a tiny armored character carry a task across a workshop floor beats reading a log, even if the log would have said the same thing. If you've built a view like this for your own agents, I'd love to see it.
