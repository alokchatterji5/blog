The short version

A chat window isn't where project state lives, so I moved it into docs: numbered folders split by topic, a few repeating document types, and one set of files every AI reads before touching anything.

A couple of weeks into working with AI on this project I kept hitting the same wall. I'd explain a decision, a reason or a constraint in one session and by the next it was gone. Not because the AI forgot on purpose. A chat window just isn't where project state lives. It's a conversation, and then it ends.

The fix wasn't a smarter prompt. It was documentation, treated as part of the project itself instead of something I'd get to later.

One big notes file didn't hold up

I started with a single running doc, everything in one place. It broke down fast. A file mixing "why I chose this identity provider" with "what's currently broken" and "step three of a migration" isn't useful to me skimming it, and it isn't useful to an AI trying to get oriented for one task. Everything is in there, so nothing is findable.

Splitting by topic, not by date

I organised by concern instead of by when something was written. Each folder covers one topic and makes sense without the others. Click around:

Pick a folder

Each one has a single job. The numbers enforce order: you can't reasonably start on implementation before strategy exists, and a folder sitting there at 06 is a constant reminder.

Within each folder the same few document types repeat:

  • A master doc: the settled reasoning for that topic. Changes rarely, and only with real justification.
  • A tracker: what's done, in progress, blocked. Updated constantly, more disposable in spirit even though I keep the history.
  • A log: not a tracker but a record of decisions and mistakes. It answers "why did we do it this way" and "what went wrong last time" without anyone having to remember.

The files every AI reads first

At the root are a few files that aren't about the homelab itself. They're about how to work on it. One is model-agnostic: rules of engagement, what's settled and shouldn't be re-litigated, what to ask before touching something. On top of that each model has its own short file with quirks specific to it, such as how Claude should approach a session versus how Gemini should. Same rules, small adjustments for how each one actually behaves.

Every session, whichever model shows up, reads these first. It's the context I never have to repeat.

What it gets me

Mostly speed. A new session doesn't start with me re-explaining history. It reads the relevant docs and it's oriented in minutes, instead of relitigating decisions from memory, mine or its.

The bigger win is consistency. Nobody remembers every decision correctly after enough time, me included. The project's memory no longer depends on my memory or on any one session getting it right. It depends on the docs staying current, and keeping them current is something AI now handles, since that's exactly the upkeep that used to get skipped.
