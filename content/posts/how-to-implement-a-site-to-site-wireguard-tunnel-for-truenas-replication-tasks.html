The short version

WireGuard runs on a pfSense router at each site, and the two routers form a tunnel even though both public IPs change. TrueNAS gets a static route to the tunnel subnet and a replication task over SSH. Nothing is exposed to the public internet.

My homelab is Marvel-themed, and the primary server is at home. The secondary sits at a friend's house as the backup, in case something happens to mine. The primary does the daily work: media streaming, file sharing, web hosting.

The problem is that both sites have dynamic public IPs, which change often and unpredictably, so a direct connection is awkward. I also did not want to expose either server to the internet. WireGuard fixes both: it authenticates and encrypts with public keys, it is small and fast, and it does not care that the IPs move.

The steps

The WireGuard and firewall steps are the same on both routers. Pick a tab for what happens where.

1. Install WireGuard on pfSense

I used the WireGuard package from the Package Manager in the pfSense web interface.

2. Generate keys and swap public keys

On the WireGuard tab I generated a private and public key on each router, then copied the public keys across so each router has the other's.

3. Create the tunnel

One tunnel per router: interface name, listening port, private key, peer public key, peer endpoint and allowed IPs. Enable WireGuard and apply.

4. Assign the interface

Assign the tunnel to an interface, enable it, set IPv4 to Static IPv4, give each side an address from the same subnet, and set the MTU to 1420.

5. Firewall rules

On the WAN interface, allow UDP to the WireGuard port. On the WireGuard interface, allow any traffic from the WireGuard peers.

6. Static route on each TrueNAS

In the TrueNAS web interface, add a static route for the WireGuard subnet. Destination IP and CIDR mask, with the gateway set to the WireGuard interface IP on the pfSense router.

Prepare the data

Create the dataset for the data to sync, plus a user account and an SSH key pair for replication. Enable the SSH service.

Create the replication task

Set the source dataset, destination server, destination dataset, SSH key pair and schedule. I also enabled "Replicate over SSH (BETA)", which lets the task use the WireGuard tunnel as the replication network.

Run it

Hit "Run Now", watch progress and status in the TrueNAS interface, and check that the data actually arrived on the destination.

Prepare the destination

Create the dataset and user account, enable the SSH service, and add the source server's SSH public key to the authorized keys file.

Then wait

The destination has nothing else to configure. The source drives the replication.

No config files hereThe original post described these steps in prose and did not include the actual pfSense or WireGuard settings, so I have not made any up. Keys, ports and subnets are yours to choose.

The result is that I sync from the primary to the secondary securely, without leaning on the public internet or static IPs. The real value is knowing there is a copy elsewhere if disaster hits.
