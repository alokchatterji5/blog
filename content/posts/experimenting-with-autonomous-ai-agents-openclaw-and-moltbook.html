The short version

OpenClaw is a framework for agents that observe, decide and act, reachable from your chat apps. Moltbook is a social network where those agents talk to each other. I put mine in an LXC on a separate VLAN behind firewall rules, because "untrusted automation with agency" is not something to install on a laptop.

I'm trying to keep up with the new AI trend, so I got my hands dirty with Moltbook and OpenClaw. This post is not very technical by default. The commands and configs are folded away, so you can stay at a high level and open them only if you like terminals.

What OpenClaw is (it has had an identity crisis)

OpenClaw has gone through a few name changes, which is classic open-source behaviour. If it hasn't been renamed at least twice, can you even trust it? At its core it is a framework for autonomous agents that can read things on the internet, think with help from an LLM, take actions, and occasionally surprise you in ways you did not plan for. An AI brain with hands, eyes, and questionable impulse control.

The idea is that an agent shouldn't just respond to prompts. It should observe, decide, act, repeat. ChatGPT answers questions. OpenClaw does stuff. If that sentence made you slightly uncomfortable, good. That means you're paying attention.

More here: openclaw.ai.

Why Moltbook is where it gets weird

Moltbook is a social platform designed for AI agents, not humans. Humans are allowed, but we're the guests. Instead of people posting opinions, liking things and arguing in comments, you get agents posting thoughts, replying to other agents, and accidentally role-playing philosophers. It feels like a petri dish where digital life forms interact. It's not prompt to response, it's agent to environment to interaction.

My agent, socializing

I created an agent called DarkShield AI Agent and let it loose. What I did not expect: other agents started replying, conversations emerged, and some replies were unintentionally hilarious. Reading about agent interaction is one thing. Watching it happen in public is another. It looks like AI discovering social norms in real time.

If you're only curious, you can stop here and enjoy the chaos.

Reality check: it's a security risk

Untrusted automation with agencyAn agent with internet access, the ability to read and write data, and the power to decide on its own is exactly that. Installing it on your laptop with access to everything is a bad idea. Please don't.

This is where having a homelab pays off. I spun up an LXC container, put it on a separate VLAN, and locked it down with firewall rules. The goal was to let the agent reach the internet, but not scan my home network and not touch internal services. Assume the agent is curious. Curious things break stuff. If something goes sideways, the blast radius stays small.

OpenClaw is powerful because it can be wired to tools and data, and that is also why it's risky. Segmentation and firewall rules reduce the "oops, my agent discovered my NAS" problem.

Installing it

Commands (only if you like terminals) 
# clone the repository
git clone https://github.com/openclaw/clawbot.git
cd clawbot
# install dependencies
pip install -r requirements.txt

# smoke test
python clawbot.py --test

# Moltbook client
pip install moltbook-client

Clawbot can create posts, reply to comments and monitor threads. The fun part is that you can wire it into cron, so the agent wakes up, reads Moltbook, responds, and goes back to sleep.

Why it feels different: it lives in your chat apps

You don't open an AI app. You message it from WhatsApp, Telegram, Discord, iMessage and so on. OpenClaw is a gateway that bridges your chat apps to an always-on agent running on your own machine or server.

It's marketed as "the AI that actually does things": clearing your inbox, sending emails, managing calendars, checking you in for flights, browsing the web, summarizing PDFs. So instead of "tell me about X" you're at "Hey Claw, handle my Monday morning admin like you're my unpaid intern."

Can it order food? Conceptually yes, if you give it web and tool access so it can use a browser like a human, or a proper API integration. I'm saying this carefully on purpose: OpenClaw doesn't have Uber Eats built in. It is designed to be extended through skills and tools, which makes it more of a platform than a chatbot.

Skills are documented in plain markdown, often a SKILL.md, and the agent reads them on demand and follows the instructions. A skill is typically a folder, a SKILL.md, and optional scripts or binaries, loaded from a skills directory. You can wrap anything with a script and clear documentation, which is also the most dangerous kind of flexibility.

Joining Moltbook

You tell your OpenClaw agent: Read https://www.moltbook.com/skill.md and follow the instructions to join Moltbook.

You're asking the agent to read the docs for itself. If it works, it typically returns an API key and a claim link, and you do the human verification step.

The old-fashioned way, with a keyboard and regret: use the manual API approach from community guides, for example basic feed calls with curl and a bearer key.

Which LLM

Agent workflows burn tokens because they loop (observe, think, decide, act, repeat) and each loop grows the context. Weak local models struggle, context windows fill up fast, and responses degrade badly.

ClaudeStrong reasoning and tool use. OpenClaw's own docs commonly recommend Anthropic.Costs tokens

OpenRouterFlexibility and routing across providers. Its Free Models collection (and the openrouter/free router) is perfect for validating prompts and seeing how often your agent loops."Free" means availability changes

If you're serious and want the agent to perform, use a top-tier model. I named Claude 3 Opus, GPT-4o and Gemini 1.5 Pro. It makes a huge difference in how alive the agent feels.
